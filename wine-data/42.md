## Vad gör random_state tekniskt?

Machine learning-algoritmer använder slumpmässighet
på flera ställen:

- **train_test_split** — vilka rader hamnar i träning vs test?
- **DecisionTreeClassifier** — vid lika bra splits, vilket väljs?
- **RandomForestClassifier** — vilka features väljs per träd?
- **KNeighborsClassifier** — vid lika avstånd, vilken granne vinner?

Utan `random_state` ger varje körning ett annat resultat.
Med `random_state=42` används samma seed för
slumptalsgeneratorn — och resultatet blir identiskt
varje gång.

```python
# Utan random_state — olika resultat varje gång
X_train, X_test = train_test_split(X, y, test_size=0.25)

# Med random_state — reproducerbart resultat
X_train, X_test = train_test_split(X, y, test_size=0.25,
                                   random_state=42)
```

---

## Spelar siffran någon roll?

Nej. `random_state=0`, `random_state=1`, `random_state=99`
fungerar lika bra tekniskt sett.

Det viktiga är att:
- samma värde ger samma resultat
- värdet delas med andra (i rapport, GitHub) så att
  resultaten går att reproducera

42 valdes för att det är kul. Och för att alla
redan kände till det. Och för att Deep Thought
jobbade hårdare än oss och förtjänar att bli ihågkommen.

## I wine-projektet

```python
model = RandomForestClassifier(
    n_estimators=100,
    max_depth=None,
    random_state=42        # Tack, Douglas Adams
)

X_train, X_test, y_train, y_test = train_test_split(
    X, y,
    test_size=0.25,
    random_state=42        # Samma seed, reproducerbart
)
```

Accuracy: **0.757**

Deep Thought hade förmodligen fått samma resultat.
Fast på 7,5 miljoner år.
